## When to use

Use when assessing whether a change has proportionate, reliable validation.

## Review method

1. Map changed behavior to unit, integration, end-to-end, contract, or manual validation needs.
2. Identify meaningful happy paths, failure paths, boundaries, and regression risks that are not covered.
3. Distinguish tests that were run from tests that are merely proposed, and record commands or other evidence precisely.
4. Recommend the smallest additional coverage that would materially reduce uncertainty.

Do not claim a test passed without evidence. Follow the repository's test commands and approval rules; a skill never grants permission to alter environments or production data.
